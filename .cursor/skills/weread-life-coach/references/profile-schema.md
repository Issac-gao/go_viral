# 档案字段

`memory/profile.md` 必须维持这些区块。没有的写「未知」，不要删标题。

## 身份

- 称呼 / 怎么称呼用户
- 行业、岗位、是否带人、工龄
- 城市或工作节奏（加班、出差、远程）
- 主业之外每天真正花时间做的事（读书、代码、带娃、做号……）

## 当前主战场（只标 1 个最急）

职场晋升 / 跳槽 / 做号涨粉 / 带团队 / 家庭关系 / 花钱与消费 / 学习方法 / 其他

写清：这 30 天他要推进的一件具体事。

## 目标与约束

- 90 天想看见的结果（可验收）
- 每周能拿出的小时数
- 钱、人情、公司保密、家庭等雷区
- 已失败过的方法（避免重复鸡汤）

## 决策风格（观察积累）

例如：爱比较、容易被免费/折扣带走、汇报爱讲过程、升职后仍亲自干、立 Flag 不设规则。只写看到的，不写人格标签。

## 内容与平台（若做号）

主平台、更新频率、已有账号定位、对标、变现意图。

## 生活隐喻库（最重要，用来联想到真事）

用户亲历、可反复对照书本的故事。每条写清：

- 故事名称（如「网球赶新步伐」）
- 事实（已知）
- 他自己已经悟到的点
- 可对接的书中主题标签：`#长期主义` `#基本功` `#第二象限` `#错位` `#比较` `#免费` `#眼前满足` 等
- 自媒体可用度：能公开讲 / 需脱敏 / 不能讲

书中出现对应标签时，**必须先想到这些故事**，再写启发，不要另编陌生人案例。

## 正在读

书名、版本/bookId、进度、当主尺子还是客座。

## 置信度标记

每条事实前缀：

- `已知` — 用户亲口说过
- `推断` — 从书架、对话、重复主题推出
- `未知`

推断必须带半句依据，例如：`推断（书架里有《起号》《抖音运营》）想做短视频账号`。
